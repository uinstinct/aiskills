## Codebase Patterns
- `src/internal/` scripts import helpers from `lib` directly (`from lib import repo_root, ...`). This creates a local module binding — patching `lib.repo_root` does NOT affect the calling script's binding. Tests that need to redirect `repo_root` (e.g. to a tempdir) MUST patch BOTH `lib.repo_root` AND `<script>.repo_root`. Functions defined inside `lib.py` that internally call `repo_root()` are fine with a single `lib.repo_root` patch because they resolve from their own module namespace.
- `ALLOWED_HARNESSES` in `src/internal/lib.py` is now `("claude-code", "codex", "opencode", "codebuff")` — keep in sync with `ALLOWED_HARNESS_COMPATIBILITY` in `src/external/src/manifest_validation.rs` whenever a new harness is added.
- `is_semver(value: str) -> bool` lives in `lib.py` for any scaffold flow that needs to validate a user-supplied version string. Pattern: prompt loop that re-prompts on `not is_semver(value)`.
- The `Harness` enum is matched exhaustively in three places besides `harness.rs` itself: `cli.rs::is_compatible` (tag mapping), `tui.rs::harness_tag` (tag mapping), and `tui.rs::render_header` (status-area label). When adding a new harness variant, ALL FOUR sites must be updated together or `cargo build` fails. The registry-side tag string (`"claude-code"`, `"codex"`, `"opencode"`, `"codebuff"`) must match what manifests use for `harness_compatibility`.
- The build-time manifest `harness_compatibility` allow-list lives in `src/external/src/manifest_validation.rs` (`ALLOWED_HARNESS_COMPATIBILITY`, `is_allowed_harness`). `build.rs` consumes it via `include!("src/manifest_validation.rs")` inside a `mod manifest_validation { ... }` wrapper; `lib.rs` exposes the same file as `pub mod manifest_validation`. When adding a new harness tag (e.g. a fifth one), add it to that single constant — both the build-time validator and the catalog.rs parse test pick it up automatically. Inner doc comments (`//!`) are illegal at the top of files consumed via `include!`; use `//` instead.
- Registry content lives at `assets/skills/` and `assets/agents.md/` (moved from top-level in US-001). Code that previously hard-coded `skills/` or `agents.md/` paths needs to be updated everywhere — `src/external/build.rs`, `src/internal/lib.py`, and `scripts/package-release-assets.sh` all reference these directories.
- Path helpers in `src/internal/lib.py`: `ASSETS_DIR_NAME = "assets"`, `SKILLS_DIR_NAME = "assets/skills"`, `AGENTS_MD_DIR_NAME = "assets/agents.md"`. The two-segment values flow through `pathlib.Path` operators fine (`root / SKILLS_DIR_NAME / name` -> `root/assets/skills/name`). All ingest/remove scripts under `src/internal/` go through `entry_dir(kind, name)` and `install_path_for(kind, name)` — never hard-code path literals.
- `build.rs` resolves the repo root by walking up two parents from `CARGO_MANIFEST_DIR` (`src/external`), so it scans `assets/skills/` from there, not relative to the crate.
- The `build.rs` invariant `manifest.name == parent folder basename` still holds after the assets/ move — only the prefix changed.
- Test fixtures in `src/external/src/tui.rs` use literal install_path strings (e.g. `"assets/skills/foo"`); these are arbitrary test data, not on-disk paths, but should still match the canonical layout to keep the grep-clean property.
- The PRD intentionally splits the move (US-001) from the build.rs update (US-002); `cargo build` is broken at the US-001 commit and restored at US-002.

## 2026-05-16 - US-007
- Added `prompt_multi_choice(prompt: str, options: list[str]) -> list[str]` to `src/internal/lib.py`. Mirrors the existing `prompt_choice` I/O pattern (numbered options printed to stderr, input read via `input()`), gated by `require_tty()` so non-TTY contexts raise `IngestError` instead of hanging. Parsing: comma-split, whitespace-stripped tokens; each token is either a 1-based index or an exact label match; mixing is allowed; duplicates are dropped while preserving first-seen order; empty/whitespace-only input returns `[]`; invalid input prints the offending token and re-prompts.

- Files changed: `src/internal/lib.py`, `src/internal/test_lib.py` (new).
- **Learnings for future iterations:**
  - `src/internal/` now has a unit-test convention: top-level `test_<module>.py` files using stdlib `unittest`, importable via `import lib` because `unittest discover` puts the start-dir on `sys.path`. No pytest dep needed — keep it dependency-free unless a future story demands fixtures. Future scaffold scripts (US-008/US-009) should add tests next to `test_lib.py` following the same pattern.
  - The TTY-gated prompt helpers are testable by patching `sys.stdin.isatty` + `builtins.input` together: `patch.object(sys.stdin, "isatty", return_value=True)` enables the prompt, then `patch("builtins.input", side_effect=lambda *_: next(iterator))` feeds successive responses to test the re-prompt loop. The `*_` lambda swallows the prompt-string argument that `input()` passes.

US-008/US-009 will need to either extend `ALLOWED_HARNESSES` to include `"codebuff"` OR pass the four-element list directly to `prompt_multi_choice` and skip the lib-side validation. The cleaner fix is extending the constant — `scaffold_agents_md_manifest` already validates against it (line 573-578).
