## Codebase Patterns
- Crate layout (US-018): `src/external/` is a `[lib]` + `[[bin]]` package. The library (`src/lib.rs`) re-exports all modules as `pub mod` so integration tests under `tests/*.rs` can `use instinctagents::{installer, state, harness, ...}` directly. main.rs is now a thin entry that imports `cli` + `tui` from the lib. When adding a new module, declare it in BOTH `src/lib.rs` (`pub mod foo;`) AND keep file at `src/foo.rs` — there is no longer a per-module declaration in main.rs. Cargo auto-detects lib+bin with the same name (`instinctagents`) without explicit `[lib]` config.
- Integration-test shared helpers (US-007/018): `src/external/tests/common/mod.rs` is the single source for `fake_claude_project()` / `fake_codex_project()` / `fake_opencode_project()` / `mock_github_releases(...)` / `build_skill_tarball(root, &[(rel, bytes)])`. The tarball helper produces a gzipped tar with a single top-level directory `<root>/` containing the files — same layout as US-029's release packaging. When a new integration test needs to fabricate an archive, reuse this helper instead of inlining its own gz/tar boilerplate (it was moved out of installer.rs's `#[cfg(test)] mod tests` precisely so multiple test files can share it).
- Integration tests bypass the network (US-018 hook): tests call `installer::install_skill_from_tarball` / `install_agents_md_from_tarball` directly with in-memory archives. DO NOT route integration tests through `fetch_and_install_*` — those hit real github.com. The mockito-based `mock_github_releases` helper exists for future stories that need to exercise `http::download_release_asset_from(base_url, ...)`-style seams; the install/remove flow doesn't need it.
- Compat-gate chokepoint (US-018): the `--force` vs `is_compatible(entry, harness)` decision lives in `cli::check_compat(entry, harness, force) -> Result<(), CliError>` (returns `CliError::Incompatible { name, allowed }` when blocked). Both Skill and AgentsMd branches of `run_add` call it. If a future story adds another install path (e.g. dry-run, batch), call `check_compat` rather than reimplementing the gate. Unit tests for the gate live in `cli::tests::check_compat_*` using synthetic `CatalogEntry` literals — that's the pattern for testing CLI gates without a non-universal real catalog entry.
- Curl installer contract (US-017): `install.sh` at repo root is the public install path. Uses `set -euo pipefail`. `REPO` defaults to `uinstinct/aiskills` and is overridable via `INSTINCTAGENTS_REPO` env — keep this env knob if the script grows, integration tests (e.g. US-018+) will rely on it to point at a mock/local server. Linux x86_64 ONLY: `uname -s == Linux` AND `uname -m ∈ {x86_64, amd64}`; anything else exits 1 with a clear `error: unsupported OS/architecture ...`. Latest tag is parsed from GitHub's `/releases/latest` JSON via a sed scanner on `"tag_name":"..."` — same hand-rolled-no-deps pattern as `update::parse_tag_name` in update.rs. The asset filename is hardcoded to `instinctagents-linux-x86_64` (must match the release-workflow rename in US-030). Final binary lands at `./instinctagents` with `chmod +x`. No system-wide install — never write outside the cwd. Success prints `Run ./instinctagents to start.` exactly (AC-string). `shellcheck install.sh` is the only lint gate; CI in US-028 should add it.
- CLI contract (US-016): `cli::Cli` (clap v4 derive) is the binary's first stop. Global flags `--force` / `--verbose` are `global = true` so they parse before OR after the subcommand. `--non-interactive` is TOP-LEVEL only — `main.rs` checks `cli.non_interactive` to decide TUI vs `cli::run_non_interactive(&cli, &cwd)`. Subcommands: `Add` / `Remove` with `ItemArgs { --name, --type? }`; `ItemType` clap value names are `skill` and `agents-md` (note hyphen). Type-disambiguation lives in pure `resolve_item_type(name, requested, has_skill, has_agents_md)` — clap can't express "required only when names collide", so the AC's "required only when a skill and agents.md integration share the same name" is enforced post-parse: for `Add` lookup against `catalog::SKILLS`+`AGENTS_MD`; for `Remove` against `state.installed_skills`+`installed_agents_md`. Both ambiguous AND unknown-name cases get distinct errors. `--force` is checked ONLY against `is_compatible(entry, harness)` (the US-016 wording: "override compatibility checks") — US-018's AC later mentions `--force=skip` / `--force=overwrite` for folder conflicts, but US-016 keeps `--force` boolean. If US-018 needs richer semantics, evolve the flag there (consider a separate `--on-conflict skip|overwrite|rename` to keep `--force` orthogonal).
- `tui::run(verbose: bool)` (US-016): the verbose flag is plumbed into the `update::check` fetcher closure as the ONLY place silent errors become loud. This closes the US-015 deferred-logging contract without touching `update::check`'s silent-swallow semantics. Pattern: wrap the inner `http::fetch_*` call with `.map_err(|e| { if verbose { eprintln!(...); } e })?`. If a future story adds more passive probes, follow this seam — don't introduce a `log` crate / `env_logger` for one-line stderr.
- `cli::CliOutcome` / `CliError` are the structured return of `run_non_interactive`. `main.rs` prints `CliOutcome` via Display on stdout (success), `CliError` via Display on stderr with exit 1 (failure). When adding new non-interactive operations, extend BOTH enums rather than adding `println!`/`eprintln!` calls inside cli.rs — the boundary stays tidy and tests can match on enum variants.
- `cli::is_compatible(entry, harness)` duplicates the row-dimming rule from `tui::harness_tag` instead of importing it. Reason: `harness_tag` is `pub(crate)` and lives in tui.rs because that's where its only existing call site is. If a third caller appears, factor it into `harness.rs` as `Harness::registry_tag(self) -> &'static str` and converge both call sites. Until then the duplication is two lines.
- Update check contract (US-015): `update::check(project_root, repo, current_version, now, fetcher) -> UpdateStatus` is the only public orchestration entry — it reads `.instinctagents` (24h TTL via `update::cache_ttl()`), invokes `fetcher` only when stale or missing, persists `last_update_check + latest_known_version` on success, falls back to cached value on fetcher error, returns `Unknown` only when both cache AND network are unavailable. `fetcher: FnOnce() -> Result<String, HttpError>` — the closure is injected so tests can stay offline. The production fetcher in `tui::run()` is the canonical pattern: `http::fetch_latest_release_json(REGISTRY_REPO)` -> `update::parse_tag_name(body).ok_or(HttpError::Malformed { url })`. Errors at this layer are SILENT (AC: "Network errors silent (do not block tool)"); verbose stderr logging is deferred to US-016 when `--verbose` lands. `UpdateStatus { UpToDate { current }, Available { current, latest, release_url }, Unknown { current } }` is the only thing the TUI reads. Banner renders above the tabs row (top-level Layout, not inside any tab body) — AC: "any tab". `parse_tag_name` is a hand-rolled scanner on `"tag_name":"..."` to avoid pulling in `serde_json` for one field; `compare_versions` zero-pads the shorter side so `0.1` == `0.1.0`.
- `App::new(project_root, harness)` is a TEST-ONLY constructor (and is `#[cfg_attr(not(test), allow(dead_code))]`) — it defaults `update_status` to `Unknown { current: CARGO_PKG_VERSION }` so tests never touch the network. Production code goes through `App::new_with_update(project_root, harness, status)`, called once from `tui::run()` AFTER `update::check` finishes. When adding more startup-time async-ish probes, mirror this seam: compute the result in `run()`, pass it into the App constructor — don't bake network calls into `App::new`.
- `HttpError::Malformed { url }` covers a 200 OK with an unexpectedly-shaped body (e.g. GitHub `/releases/latest` JSON with no `tag_name`). Distinct from `BodyRead` (I/O failure mid-read) and `UnexpectedStatus` (non-200/404 HTTP status). Use Malformed for "the server answered fine, but we couldn't parse what we needed".
- `http::fetch_latest_release_json(repo)` calls `GET https://api.github.com/repos/<repo>/releases/latest` with the `instinctagents/<version>` User-Agent (GitHub rejects requests without UA) and `Accept: application/vnd.github+json`. Timeouts are deliberately shorter than the asset-download path (5s connect / 10s read) — this is a passive probe that must never block the UI. `fetch_latest_release_json_from(base_url, repo)` is the test variant pointing at mockito.
- `chrono::Duration::hours(24)` is the cache TTL constant. Don't hard-code "24h" anywhere else — call `update::cache_ttl()` so a future tune is one-spot. `is_cache_fresh(last_check, now)` returns `false` for `None` (no cache => stale by definition).
- List tab contract (US-014): `tui::build_list_rows(state, harness) -> Vec<ListRow>` (pure) yields skills first, then agents.md, each row carrying { kind, name, version, source_url, install_path }. For agents.md entries `install_path` is composed as `<harness.agents_md_file()> (block: <delimiter_id>)` (or `(block: <id>)` if harness is None) — this is the only place we humanize the agents.md "install location" for display. `App` caches the list in a `list: Vec<ListRow>` field populated in `App::new` and re-derived by BOTH `refresh_add_rows` and `refresh_remove_rows` so the List tab is always in sync after any mutation. List tab is NOT gated by harness detection (it's read-only) — `Tab::requires_harness()` still returns false for List.
- Remove path contract (US-013): `installer::remove_skill(project_root, harness, name) -> Result<(), InstallError>` deletes `<harness>/skills/<name>/` (no-op if missing) and prunes `state.installed_skills` by name. `installer::remove_agents_md(project_root, harness, name) -> Result<bool, InstallError>` removes the delimited block from `<harness.agents_md_file()>` and prunes `state.installed_agents_md` by name; returns `true` if the block was found, `false` if missing (state still pruned). Pure transform: `remove_block(content, name) -> (String, bool)` mirrors `upsert_block` and uses the same first-start-then-first-end-after-start search so unrelated blocks are preserved byte-for-byte. The block is removed BYTE-INCLUSIVE — surrounding whitespace (blank lines `upsert_block` inserted before the block) is left in place; that keeps the contract symmetric (no special-case cleanup) but means repeated install→remove cycles can accumulate blank lines. Acceptable for now; if it becomes annoying, add a `\n\n` collapse pass.
- Skill install contract (US-012): `installer::install_skill_from_tarball(project_root, harness, name, version, source_url, tarball_gz, on_conflict)` is the pure-bytes install path; `installer::fetch_and_install_skill(...)` is the thin HTTP wrapper that fetches via `http::download_release_asset(REGISTRY_REPO, REGISTRY_TAG, skill_asset_name(name, version))`. Tarball layout per US-029: top-level directory `<name>/` containing the skill's files; extract destination is `project_root.join(harness.target_folder())` so files land at `.claude/skills/<name>/...`. `OverwriteAction { Skip, Overwrite, Rename }` controls existing-folder behavior. Rename uses a sibling scratch dir `.instinctagents.rename.<new_name>/` and `fs::rename` so the existing folder is byte-identical; new_name is `<name>-2`, `-3`, … (next free). `SkillInstallOutcome` reports back which path was taken. State upsert matches by `name` in `installed_skills`.
- tar 0.4 + flate2 1 are pure-Rust (flate2 uses miniz_oxide by default). `tar::Archive::unpack(dest)` + `Entry::unpack_in` validate paths and reject entries with `..` or absolute paths — DO NOT switch to manual per-entry iteration without re-implementing that path-traversal check. `archive.set_overwrite(true)` is needed for re-install paths; `set_preserve_permissions(false)` keeps cross-OS installs sane.
- agents.md tarball install (US-012): `installer::install_agents_md_from_tarball(project_root, harness, name, version, source_url, tarball_gz)` extracts `<name>/snippet.md` from the gzipped tar and delegates to `install_agents_md_snippet`. Snippet filename is hardcoded to `DEFAULT_SNIPPET_FILE = "snippet.md"`; the catalog doesn't yet expose `snippet_file` overrides — when build.rs is extended to bake that field in, pass it through here.
- Registry endpoint constants in installer.rs: `REGISTRY_REPO = "uinstinct/aiskills"`, `REGISTRY_TAG = concat!("v", env!("CARGO_PKG_VERSION"))`. Asset filename helpers: `skill_asset_name(name, version) = "skill-<name>-<version>.tar.gz"`, `agents_md_asset_name(...) = "agents-md-<name>-<version>.tar.gz"` — match the US-029 packaging contract.
- US-018 (integration tests) hook: `fetch_and_install_skill` / `fetch_and_install_agents_md` are hardcoded against the real `https://github.com` base. When wiring end-to-end tests against mockito, add `*_from(base_url, ...)` variants mirroring the existing `http::download_release_asset_from`. Don't try to test the existing `fetch_*` functions directly — exercise `install_skill_from_tarball` + `install_agents_md_from_tarball` with in-memory archives instead.
- TUI Add tab (US-012): `tui::App { current_tab, harness, project_root, should_quit, add: AddTabState }`. `AddTabState { rows, cursor, selected, status, modal }` keeps Add-tab state separate. Build the row list with the pure function `build_add_rows(catalog::SKILLS, catalog::AGENTS_MD, &state, harness)` — refresh by re-running it after each install. Cursor is an index into the flat `rows` vec (skills first, then agents.md); render inserts section header items, see `cursor_to_list_index` for the mapping. Modal is rendered as a centered popup via `Clear` + `Paragraph`; when `app.add.modal.is_some()` keys are dispatched to `handle_modal_key` instead of normal navigation. `OverwriteAction` from the modal fans out to all conflicts in a single batch install.
- `harness_tag(Harness)` maps detected harness to the manifest's `harness_compatibility` string ("claude-code" / "codex" / "opencode"). A row is incompatible iff `harness_compatibility` is non-empty AND doesn't contain `harness_tag(detected)`. Empty list = universal compatibility. The same rule is used to dim rows and to block Space-toggle on incompatible items.
- `tempfile::TempDir::into_path` is deprecated; use `TempDir::keep()` when you need to leak the directory beyond the guard's drop (e.g. for tests that construct an App with a path that must outlive the test scope).
- agents.md injection contract (US-011): `installer::upsert_block(content, name, snippet) -> String` is the pure transform; `installer::upsert_block_in_file(path, name, snippet) -> io::Result<()>` is the fs wrapper (creates the file if missing, treats NotFound as empty). Delimiters: `<!-- instinctagents:start:<name> -->` / `<!-- instinctagents:end:<name> -->`. Block format is `<start>\n<body>\n<end>` with no trailing newline INSIDE the block; the wrapper adds one trailing `\n` after appending. Replace-in-place uses `find(start)` then `find(end)` on the slice AFTER the start — this guarantees we never capture an earlier orphan end-delim. Bytes outside the delimiter range are preserved byte-for-byte. The "blank line before" rule applies only when the existing content is non-empty (empty file just gets `<block>\n`). Snippet body is trimmed of leading/trailing `\n` so callers don't have to normalize. US-013's removal path should use the SAME delimiter pair to find and delete the block.
- Full install path: `installer::install_agents_md_snippet(project_root, harness, name, version, source_url, snippet) -> Result<(), InstallError>` does file write + `.instinctagents` upsert in one call. State entry uses `delimiter_id = Some(name)` and `install_path = None` (mirror of skill entries). Match-by-name upsert in `state.installed_agents_md` — no duplicates. `InstallError` wraps Io + StateError with From impls.
- TUI scaffolding (US-010): `tui::run() -> io::Result<()>` is the binary's only entry. It uses `std::io::IsTerminal` on stdout — when stdout is NOT a TTY (e.g. assert_cmd pipes, CI runners), `run` returns Ok(()) IMMEDIATELY without enabling raw mode or entering the alternate screen. This is the non-interactive escape hatch every integration test relies on; do NOT remove it when US-016 adds clap. The `App { current_tab, harness, should_quit }` state is internal to tui.rs. `Tab::ALL` is `[Add, Remove, List, Update]`; `tab_disabled(tab)` returns true when `tab.requires_harness() && harness.is_none()`. Keymap: Tab/Shift+Tab/BackTab cycle, 1–4 jump, q/Esc quit. Future stories (US-012/013/014/015) should add their UI inside `render_body` keyed off `app.current_tab`, NOT by creating sibling widgets — keep the layout (header / Tabs / body / footer) intact so the keymap and quit path stay consistent.
- ratatui/crossterm versions: `ratatui = "0.29"`, `crossterm = "0.28"`. Avoid bumping to ratatui 0.30 without a deliberate decision — 0.30 requires rust-version 1.86 and split the crossterm backend into a separate `ratatui-crossterm` crate. Default features are fine. `f.area()` (not `f.size()`) is the 0.29 frame size accessor.
- State file contract (US-009): `state::ProjectState { last_update_check, latest_known_version, installed_skills, installed_agents_md }` with `InstalledItem { name, version, source_url, install_path: Option<String>, delimiter_id: Option<String> }`. Persisted as TOML at `<project_root>/.instinctagents` (`state::STATE_FILE_NAME`). `ProjectState::load(&Path)` returns `Self::default()` on NotFound (not an error). `ProjectState::save(&Path)` is atomic: write to `.instinctagents.tmp` then `fs::rename`. The same struct holds the auto-update cache fields (`last_update_check`, `latest_known_version`) — US-015 reuses these; don't introduce a separate file. Use `install_path` for skills (e.g. `.claude/skills/<name>/`) and `delimiter_id` for agents.md (equals the entry's `name`); both are Option so one struct serves both lists. `StateError` variants: Io / Parse / Serialize.
- TOML serialization gotcha: with the `toml` crate, top-level scalar fields must appear before arrays-of-tables (`Vec<T>`) in a struct, otherwise serialization errors. Keep scalars (Option<…>) at the TOP of any struct that ends up at the TOML root.
- Runtime crypto/clock/serialization deps live in `[dependencies]` of src/external/Cargo.toml: `serde { features = ["derive"] }`, `toml = "0.8"`, `chrono { default-features = false, features = ["clock", "serde"] }`. `chrono::DateTime<Utc>` serializes as ISO-8601 string via serde — works fine with the toml crate without needing toml-native datetime.
- HTTP layer contract (US-008): `http::download_release_asset(repo, tag, asset_name) -> Result<Vec<u8>, HttpError>` fetches https://github.com/<repo>/releases/download/<tag>/<asset_name>. `download_release_asset_from(base_url, repo, tag, asset_name)` is the same call with the base URL injected — use it in tests against mockito. HttpError variants: AssetNotFound (404), NetworkUnreachable (Transport error), UnexpectedStatus { status }, BodyRead. Don't add a separate "network unreachable" check at call sites — match the variant.
- TLS backend is target-split in src/external/Cargo.toml: Linux uses `ureq { features = ["rustls"] }` (the shipped binary per US-017/US-030); non-Linux uses `native-tls`. The release artifact remains rustls-only — this split is purely a dev-env workaround for hosts where ring's C build chain (ranlib/CLT) is unavailable. http.rs is TLS-backend-agnostic — ureq's request API is identical. If CI (US-028) runs on macOS, it will use native-tls there; assert rustls is in effect on the linux-x86_64 release job (US-030).
- Integration tests live at src/external/tests/*.rs (each file is its own crate). The shared helper module is src/external/tests/common/mod.rs, included into each test file via `mod common;`. Add new helpers there rather than duplicating per-file. Note: tests/common/mod.rs carries `#![allow(dead_code)]` because each test file only uses a subset of the helpers and Rust would otherwise warn about the unused ones under `-D warnings`.
- Test helpers (US-007): `common::fake_claude_project()`, `common::fake_codex_project()`, `common::fake_opencode_project()` each return a `tempfile::TempDir` seeded with the minimal harness signal (CLAUDE.md / AGENTS.md / opencode.json). `common::mock_github_releases(tag, &[(asset_name, &[u8])])` returns a `MockReleases { server: ServerGuard, _mocks: Vec<Mock> }` — the `_mocks` field MUST stay alive (mockito Mock removes itself from the server on drop). Use `.url()` to get the base URL.
- Dev-dependency stack: tempfile (US-006), mockito 1, assert_cmd 2, predicates 3 (all added in US-007). Use `assert_cmd::Command::cargo_bin("instinctagents")` to invoke the built binary from integration tests; combine with `predicates::str::contains` for stdout assertions.
- Harness detection contract (US-006): `harness::detect(&Path) -> Option<Harness>` with priority ClaudeCode > Codex > OpenCode (first match wins). Signals — ClaudeCode: CLAUDE.md file OR .claude/ dir; Codex: AGENTS.md file OR .codex/ dir; OpenCode: opencode.json|opencode.jsonc file OR .opencode/ dir. Use `Harness::target_folder()` for skill install path and `Harness::agents_md_file()` for the harness-specific instruction file (Codex AND OpenCode both use AGENTS.md — don't assume the file name is unique to a harness).
- `tempfile` is a dev-dependency in src/external/Cargo.toml — reuse `tempfile::TempDir` for any fs-touching unit test instead of hand-rolling temp dirs. US-007's tests/common helpers will return `TempDir`s built on top of this.
- Module stubs follow a convention: each src/external/src/<mod>.rs starts with `//!` doc naming the story that fills it in. When implementing a stub, update the doc comment to past tense ("Implemented in US-XYZ.") rather than removing it; `#![allow(dead_code)]` at the top is fine while later stories aren't yet consuming the items (remove it as soon as consumers appear).
- Registry repo layout: skills/<name>/, agents.md/<name>/, src/external/ (Rust CLI), src/internal/ (Python ingest scripts), docs/, scripts/, .github/workflows/.
- Top-level mapping.yml is the registry catalog. The build-time embedded catalog (US-005) is generated by src/external/build.rs from per-entry manifest.yml files (NOT from mapping.yml); install/remove paths (US-012/US-013) read from the embedded `catalog::SKILLS` / `catalog::AGENTS_MD` constants.
- Two manifest variants share core fields (name, description, version, harness_compatibility) but each gets one optional type-specific field: skills -> entrypoint (default SKILL.md); agents.md -> snippet_file (default snippet.md). The build script only needs the core four fields, but accepts and ignores the extras via serde's default behavior — DO NOT add `#[serde(deny_unknown_fields)]` to the build-side Manifest struct.
- `name` in manifest.yml MUST equal the parent folder basename — this invariant is enforced by build.rs (panics on mismatch) and is relied on by the install/remove paths.
- Allowed harness_compatibility values are exactly: claude-code, codex, opencode. Empty list / omitted = compatible with all. build.rs validates each entry against this allow-list at compile time.
- prd.json is the source of truth for story state. After completing a story, flip `passes: true` and update `notes` with what was delivered.
- Branch: ralph/instinctagents (already checked out). Commit per story with `feat: [US-ID] - [Title]`.
- Cargo layout: root Cargo.toml is a workspace with `members = ["src/external"]`, resolver = "2". The binary crate lives at src/external/ (package name `instinctagents`, edition 2021, binary target, `build = "build.rs"`). Run `cargo check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, and `cargo build --release` from the repo root. Output binary: target/release/instinctagents.
- Rust module skeleton at src/external/src/: main.rs (entrypoint, declares all sibling mods), cli.rs, tui.rs, harness.rs, catalog.rs, installer.rs, state.rs, update.rs, http.rs. Each stub carries a one-line `//!` doc comment naming the story that fills it in — keep that convention when adding new modules. catalog.rs has `#![allow(dead_code)]` because the embedded constants aren't referenced yet; remove that attribute once US-010+ start consuming them.
- Embedded catalog API: `catalog::CatalogEntry { name, description, version, harness_compatibility: &[&str], source_path }` and two `pub const` slices `catalog::SKILLS` and `catalog::AGENTS_MD`. Entries are sorted by folder name (BTreeMap iteration) so the generated file is deterministic across builds.
- build.rs locates the workspace root via `CARGO_MANIFEST_DIR/../..`. Any future build-script work must preserve this relationship — keep src/external/ exactly two levels under repo root.
- Internal Python scripts (US-019): src/internal/ holds six scripts (skill_add/remove/list, agents_md_add/remove/list) plus shared lib.py. All scripts route user-facing errors through `lib.IngestError` + `lib.fail(msg)` (one-line `error: <msg>` to stderr, exit 1); argparse handles --help and rejects malformed invocations with exit 2; uncaught exceptions are programmer bugs and surface their traceback. lib.py is the ONLY place to add cross-cutting helpers: `repo_root()` walks up for `mapping.yml`, `load_mapping()` / `save_mapping(data)` is the atomic temp-then-rename + within-section-sorted writer, `entry_dir(kind, name)` / `install_path_for(kind, name)` use `kind` literals `"skill"` / `"agents-md"`, and `find_entry` / `remove_entry` are the list mutators. Only runtime dep is pyyaml>=6.0 (requirements.txt) — anything else MUST be stdlib. Scripts are invoked from repo root as `python src/internal/<script>.py ...` (slash commands in US-025/026/027 will wrap this). `python -m py_compile src/internal/*.py` is the only typecheck gate.
- GitHub ingest helpers in lib.py (US-020): `parse_github_url(url) -> ParsedGithubUrl { kind, owner, repo, ref?, path }` where kind ∈ {repo, folder, blob, raw}. Refs containing `/` (`feature/foo`) are NOT supported — the URL form is ambiguous without a tree listing; document the limitation in any script that consumes parse_github_url. `sanitize_name` is the canonical name-derivation: lowercase, strip extension on filename-like input, replace `[^a-z0-9_-]` with `-`, collapse repeats, strip leading/trailing `-`, reject empty. HTTP layer is `http_get_bytes/text/json` over `urllib.request` (User-Agent always sent; honors `GITHUB_TOKEN` env for github.com / api.github.com / raw.githubusercontent.com URLs); all errors funnel through `IngestError`. Tree walk uses `list_tree_recursive(owner, repo, ref)` against `/git/trees/{ref}?recursive=1` — single API call beats per-directory listing; emits a stderr warning on `truncated: true`. Single-file fetch is `fetch_raw_file(owner, repo, ref, path)` against raw.githubusercontent.com. `fetch_folder_to_disk(owner, repo, ref, src_path, dest_dir, tree=)` walks the recursive tree filtered under src_path and writes every blob, returning the list of relative paths written; pass an already-fetched `tree` to avoid the second API call. Manifest scaffolding lives in `scaffold_skill_manifest` / `scaffold_agents_md_manifest` (read existing manifest verbatim if present, else prompt for description + version + (agents.md) harness_compatibility, write minimal manifest). Catalog write is `upsert_catalog_entry(kind, name, version, source_url)` which load_mapping → remove_entry → append → save_mapping, kind literals `"skill"` / `"agents-md"` (same as `install_path_for`).

- **Learnings for future iterations:**
  - ureq 2.x error model: `.call()` returns `Result<Response, ureq::Error>` where non-2xx HTTP statuses come back as `ureq::Error::Status(code, response)` (NOT `Ok`). 404 specifically maps to `AssetNotFound`; everything else is `UnexpectedStatus { status }`. Transport-layer errors (DNS, connection refused, TLS) come back as `ureq::Error::Transport(_)` → `NetworkUnreachable`. The `Response::into_reader()` step reads the body — fail it into `BodyRead`.
  - The CLT ranlib on this dev macOS is permission-locked (`Operation not permitted` even from a normal shell). Anything that pulls in `ring` (or `aws-lc-rs`) for C-compiled crypto will fail to build locally. Workaround used: target-specific TLS features in Cargo.toml so the macOS host builds ureq with `native-tls` (Apple Security framework, no C compile). The Linux release build still uses rustls per the AC. Future stories adding more crypto/TLS deps (none on the roadmap) must keep this split or document equivalent fallback.
  - mockito works fine from synchronous Rust tests: `mockito::Server::new()` spawns its own runtime internally and returns a `ServerGuard`. Use `server.url()` as the base URL, mock paths as `/owner/repo/releases/download/<tag>/<asset>` to mirror GitHub. Each test gets its own server — they don't share state.
  - Don't put the http unit tests in tests/ — this is a binary crate (no `[lib]` target), so integration tests under tests/ can't reach internal modules. Keep test coverage as `#[cfg(test)] mod tests` inside src/external/src/http.rs. The US-007 `mock_github_releases` helper is for future install/remove integration tests that exec the binary; it doesn't fit the unit-test path here.
  - GitHub's real release-download URL 302s to a signed CDN URL on a different host. ureq 2.x follows redirects by default (up to 5 hops). No special config needed, but be aware: any path that intentionally needs to NOT follow redirects must build a custom `Agent` with `.redirects(0)`.
  - On macOS, `native-tls` brings in security-framework / core-foundation — first build adds ~5s, subsequent are fast. On Linux, rustls brings ring (and its C build) — that's the path CI exercises.
  - `download_release_asset_from` accepts and tolerates a trailing slash on the base URL (`trim_end_matches('/')`). Callers don't need to normalize.
