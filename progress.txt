## Codebase Patterns
- Registry repo layout: skills/<name>/, agents.md/<name>/, src/external/ (Rust CLI), src/internal/ (Python ingest scripts), docs/, scripts/, .github/workflows/.
- Top-level mapping.yml is the registry catalog. The build-time embedded catalog (US-005) is generated by src/external/build.rs from per-entry manifest.yml files (NOT from mapping.yml); install/remove paths (US-012/US-013) read from the embedded `catalog::SKILLS` / `catalog::AGENTS_MD` constants.
- Two manifest variants share core fields (name, description, version, harness_compatibility) but each gets one optional type-specific field: skills -> entrypoint (default SKILL.md); agents.md -> snippet_file (default snippet.md). The build script only needs the core four fields, but accepts and ignores the extras via serde's default behavior — DO NOT add `#[serde(deny_unknown_fields)]` to the build-side Manifest struct.
- `name` in manifest.yml MUST equal the parent folder basename — this invariant is enforced by build.rs (panics on mismatch) and is relied on by the install/remove paths.
- Allowed harness_compatibility values are exactly: claude-code, codex, opencode. Empty list / omitted = compatible with all. build.rs validates each entry against this allow-list at compile time.
- prd.json is the source of truth for story state. After completing a story, flip `passes: true` and update `notes` with what was delivered.
- Branch: ralph/instinctagents (already checked out). Commit per story with `feat: [US-ID] - [Title]`.
- Cargo layout: root Cargo.toml is a workspace with `members = ["src/external"]`, resolver = "2". The binary crate lives at src/external/ (package name `instinctagents`, edition 2021, binary target, `build = "build.rs"`). Run `cargo check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, and `cargo build --release` from the repo root. Output binary: target/release/instinctagents.
- Rust module skeleton at src/external/src/: main.rs (entrypoint, declares all sibling mods), cli.rs, tui.rs, harness.rs, catalog.rs, installer.rs, state.rs, update.rs, http.rs. Each stub carries a one-line `//!` doc comment naming the story that fills it in — keep that convention when adding new modules. catalog.rs has `#![allow(dead_code)]` because the embedded constants aren't referenced yet; remove that attribute once US-010+ start consuming them.
- Embedded catalog API: `catalog::CatalogEntry { name, description, version, harness_compatibility: &[&str], source_path }` and two `pub const` slices `catalog::SKILLS` and `catalog::AGENTS_MD`. Entries are sorted by folder name (BTreeMap iteration) so the generated file is deterministic across builds.
- build.rs locates the workspace root via `CARGO_MANIFEST_DIR/../..`. Any future build-script work must preserve this relationship — keep src/external/ exactly two levels under repo root.

## 2026-05-15 - US-005
- Added a build script that bakes the skill + agents.md catalog into the binary at compile time.
- Files changed:
  - src/external/Cargo.toml (added `build = "build.rs"` and `[build-dependencies]` for serde + serde_yaml 0.9)
  - src/external/build.rs (new — walks <repo>/skills/* and <repo>/agents.md/*, parses manifest.yml via serde_yaml, validates name == folder name and harness_compatibility ∈ {claude-code, codex, opencode}, emits OUT_DIR/catalog_generated.rs)
  - src/external/src/catalog.rs (defines `CatalogEntry`, `include!`s the generated file to expose `SKILLS` and `AGENTS_MD`, adds two `#[cfg(test)]` unit tests; carries `#![allow(dead_code)]` until US-010+ start consuming the constants)
  - Cargo.lock (regenerated for new build-dependencies)
  - prd.json (US-005 passes -> true)
- Quality gates:
  - `cargo check` clean
  - `cargo clippy --all-targets -- -D warnings` clean (no warnings on build.rs or the new constants)
  - `cargo test` — 2 passed (catalog_sections_are_non_empty, catalog_contains_us001_example_entries)
  - `cargo build --release` produced target/release/instinctagents
- **Learnings for future iterations:**
  - The build script lives at src/external/build.rs (alongside Cargo.toml), NOT at src/external/src/build.rs. Cargo runs `build = "build.rs"` relative to the package manifest. The `//!` doc comment on build.rs is fine because Cargo never compiles it as a library — it just invokes it.
  - `include!(concat!(env!("OUT_DIR"), "/catalog_generated.rs"))` inside catalog.rs makes the generated `SKILLS`/`AGENTS_MD` constants appear as if defined in that module. Tests in the same module see them via `use super::*;`.
  - Build-time `cargo:rerun-if-changed` directives now cover `skills/`, `agents.md/`, each individual manifest.yml, and build.rs itself. Future stories that introduce new top-level catalog directories (none planned) must add another `rerun-if-changed`.
  - serde_yaml 0.9 is marked `+deprecated` upstream but is still the de facto YAML parser for serde — keep using it until / unless a migration to a maintained fork is required. Build deps don't affect the runtime binary size.
  - When build.rs panics on a malformed manifest, the cargo error surface includes the panic message verbatim. I used `.unwrap_or_else(|e| panic!(...))` instead of plain `.expect(...)` precisely so the panic message can interpolate the path AND the underlying error — keep that pattern for future builder/loader code.
  - catalog.rs currently has `#![allow(dead_code)]` because nothing reads `SKILLS`/`AGENTS_MD` yet. Remove that attribute as soon as the TUI tabs (US-010, US-012) start consuming the catalog, otherwise real dead code will start hiding behind the blanket allow.
  - source_path values are written as `<label>/<folder>` without a trailing slash (unlike `install_path` in mapping.yml which canonically ends with `/`). This is the on-repo source location, not an install target — don't confuse the two when wiring up US-012's installer.
  - Two new build-dependencies pulled in (indexmap, ryu, itoa, unsafe-libyaml, etc.) — these only affect build time, not the final binary. The release binary size from US-004 is unchanged.
