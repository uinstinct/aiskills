## Codebase Patterns
- Workspace Cargo.toml at root includes `src/external`; `cargo build` runs from root and outputs to `target/` at root level (not `src/external/target/`)
- Release workflow uses separate build jobs that upload artifacts, then a final `release` job downloads and publishes

## 2026-05-15 - US-001
- What was implemented: Split the single `release` job into `build-linux-x86_64`, `build-macos-arm64`, and `release` jobs. The macOS arm64 job runs on `macos-14`, installs Rust with `aarch64-apple-darwin` target, builds, strips, and uploads artifact. The final `release` job downloads all artifacts and publishes via softprops/action-gh-release.
- Files changed: `.github/workflows/release.yml`
- **Learnings for future iterations:**
  - Cargo workspace root is at repo root; binaries land in `target/<triple>/release/` relative to repo root
  - For multi-platform releases, use upload-artifact/download-artifact pattern with `merge-multiple: true` to collect binaries in a single publish job
  - `macos-14` GitHub runner is Apple Silicon (arm64), suitable for native `aarch64-apple-darwin` builds
